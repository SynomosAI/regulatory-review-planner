# 审查项体系

本审查项体系是制度合规审查的规则菜单。使用时应根据文档类型、用户提供材料、用户目标和可用工具选择相关审查项，而不是每次机械执行全部清单。

## 一、制度要素完整性

| key | 中文名称 | 审查重点 |
|---|---|---|
| `system_title` | 制度标题审查 | 是否存在标题，标题是否符合制度命名规范。 |
| `institutional_hierarchy` | 制度层级审查 | 是否按要求注明制度层级。 |
| `institutional_purpose` | 制定目的审查 | 制定目的是否清晰，并与业务需要相匹配。 |
| `institutional_basis` | 制定依据审查 | 制定依据是否具体、现行有效，结构上是否合理。 |
| `scope_of_application` | 适用范围审查 | 适用主体、适用活动和排除事项是否清楚。 |
| `manage_department` | 归口管理部门审查 | 归口部门及职责是否明确。 |
| `coordinating_management_department` | 配合管理部门审查 | 配合部门及职责是否分开列明，边界是否清晰。 |
| `consequences_of_violation` | 违规后果审查 | 责任追究和违规后果是否依法、适当设置。 |
| `interpretive_department` | 解释部门审查 | 解释主体是否明确，名称是否前后一致。 |
| `implementation_time` | 施行时间审查 | 是否明确施行日期或生效规则。 |
| `attachment_form` | 附件/表单审查 | 涉及审批、备案、审核流程时，是否配套必要表单或附件。 |
| `institutional_completeness_and_alignment` | 制度完整性与体系衔接审查 | 是否缺少应有模块、执行责任人、审批路径、证据留存或申诉渠道；是否与劳动合同、薪酬、休假、奖惩、信息安全等配套制度冲突或应当拆分为专题制度。 |

## 二、结构与格式

| key | 中文名称 | 审查重点 |
|---|---|---|
| `definition_and_explanation` | 定义释义审查 | 定义是否必要、准确、前后一致。 |
| `division_of_chapter` | 章节划分审查 | 章节/条款结构是否适合文档篇幅和复杂度。 |
| `supplementary_provisions_structure` | 附则结构审查 | 解释、生效、废止、适用范围等附则条款顺序是否合理。 |
| `internal_system_name_writing` | 内部制度名称书写审查 | 内部制度名称和文号是否完整准确。 |
| `attachment_name_consistent` | 附件名称一致性审查 | 附件名称是否前后一致。 |
| `clause_number` | 条款编号审查 | 条文编号是否唯一、连续，引用是否准确。 |

## 三、权责与权限

| key | 中文名称 | 审查重点 |
|---|---|---|
| `legality_of_authority` | 权限合法性审查 | 发文主体是否有权设定义务、处罚、审批或管理权限。 |
| `duty_description` | 职责描述审查 | 职责是否清楚、可执行，是否存在职责交叉或遗漏。 |
| `implied_obligation` | 隐含义务审查 | 是否在缺少程序或权限依据的情况下创设隐含义务。 |
| `approval_right` | 审批权审查 | 审批主体、阈值和程序是否清楚。 |
| `inspection_right` | 检查权审查 | 检查权限是否合法、边界是否明确。 |
| `disposition_right` | 处分权审查 | 处罚、处分、处理措施是否有依据且表述适当。 |
| `remedies` | 救济措施审查 | 申诉、纠正、补救和争议处理机制是否可操作。 |
| `discretionary_power` | 自由裁量权审查 | 裁量空间是否过宽，是否缺少标准。 |

## 四、法律与合规风险

| key | 中文名称 | 审查重点 |
|---|---|---|
| `regulation_name_validity` | 法规名称与时效性审查 | 引用的法律法规是否现行有效，名称是否准确。 |
| `higher_level_law` | 内外规冲突审查 | 是否与上位法、外部法律法规冲突。 |
| `superior_policy_conflict` | 上级制度冲突审查 | 是否与上级内部制度或模板政策冲突。 |
| `discrimination_and_fairness` | 歧视与公平审查 | 是否存在不公平竞争、歧视性待遇或排除限制竞争风险。 |
| `private_information` | 个人信息风险审查 | 个人信息收集、使用、提供是否遵循合法、正当、必要原则。 |
| `laborers_rights` | 劳动者权益审查 | 是否损害劳动者合法权益。 |
| `intellectual_property_rights` | 知识产权审查 | 知识产权归属、使用、许可或保护是否存在风险。 |
| `external_organization_name` | 外部机构名称审查 | 外部法律、机关、组织名称是否准确。 |
| `sensitive_words` | 敏感词审查 | 政治、地域、法律敏感表述是否妥当。 |

## 五、语义一致性

| key | 中文名称 | 审查重点 |
|---|---|---|
| `referent_expression_consistent` | 指代表达一致性审查 | 定义词、简称和指代对象是否前后一致。 |
| `description` | 描述清晰性审查 | 描述是否具体、可验证，避免模糊表达。 |
| `statement` | 陈述规范审查 | 陈述是否逻辑完整。 |
| `condition` | 条件审查 | 条件是否明确、可判断。 |
| `circular_dependency` | 循环依赖审查 | 条款之间是否存在循环依赖或循环引用。 |
| `prerequisites` | 前提条件审查 | 前提条件是否清楚，是否存在无法验证的“幽灵条件”。 |
| `conflicting_provisions` | 条款冲突审查 | 条款之间是否相互矛盾。 |
| `miscellaneous_provisions` | 兜底条款审查 | 兜底条款是否过宽或位置不当。 |
| `quantitative_relation_expression` | 数量关系审查 | 金额、比例、期限、范围等数量关系是否准确。 |

## 六、语言文字规范

| key | 中文名称 | 审查重点 |
|---|---|---|
| `inappropriate_word_choice` | 用词不当审查 | 是否存在过时、不准确或易误解用词。 |
| `sentence` | 句子审查 | 句子是否通顺、无歧义。 |
| `punctuation` | 标点审查 | 标点符号是否规范。 |
| `language_style` | 语言风格审查 | 语言风格是否符合正式制度文本。 |
| `prohibitive_provisions_expression` | 禁止性条款表达审查 | 禁止性要求是否清楚、边界明确。 |
| `mandatory_provisions_expression` | 强制性条款表达审查 | 强制性义务是否清楚、合法、可执行。 |
| `syllable_word_expression` | 音节词表达审查 | 是否按制度写作习惯使用更正式的双音节表达。 |
| `conjunctions` | 连接词审查 | 连接词是否准确表达并列、递进、条件、选择等逻辑关系。 |
| `zuochu_usage_norms` | “作出/做出”用法审查 | 专门用法是否准确。 |
| `huitong_shang_usage_norms` | “会同/商”用法审查 | 协调类表述是否准确。 |
| `ri_usage_norms` | “日”用法审查 | 日期和期限表达是否规范。 |
| `common_numeral_conventions` | 数字用法审查 | 中文数字、阿拉伯数字和序号用法是否统一。 |
| `typo` | 错别字审查 | 是否存在错别字、过时名称或明显文本错误。 |
